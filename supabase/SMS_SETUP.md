# ورود موبایلی با LimoSMS

اپ با `signInWithOtp` درخواست کد می‌دهد؛ Supabase کد را تولید و تأیید می‌کند و نشست معتبر برای RLS می‌سازد. تابع `send-sms` فقط کد Supabase را از طریق پترن LimoSMS ارسال می‌کند. از `sendcode` لیمو استفاده نکنید: کد تولیدشدهٔ آن با کد Supabase متفاوت است.

## راه‌اندازی

1. در پنل LimoSMS دسترسی API بگیرید و یک الگوی تأییدشده با **یک متغیر، برای کد** ایجاد کنید؛ مثلاً «کد ورود شما به هنر زندگی: [متغیر کد]». شناسهٔ الگو همان `OtpId` است.
2. در Supabase، Phone provider و ثبت‌نام کاربران جدید را فعال کنید. طول OTP را ۶ رقم، انقضا را ۱۲۰ ثانیه و فاصلهٔ ارسال را حداقل ۶۰ ثانیه قرار دهید. محدودیت‌های سروری ارسال و تأیید را تنظیم کنید؛ شمارندهٔ اپ جایگزین محدودیت سرور نیست. شماره‌های تست و کد ثابت را در محیط عملیاتی حذف کنید.
3. در Authentication → Hooks یک **Send SMS hook از نوع HTTPS** با URL زیر بسازید و signing secret آن را تولید کنید:
   `https://PROJECT_REF.supabase.co/functions/v1/send-sms`
4. فایل `supabase/functions/.env.example` را به `supabase/functions/.env` کپی کنید و سه مقدار را محلی تکمیل کنید. مقدار `SEND_SMS_HOOK_SECRET` همان secret تولیدشده با قالب `v1,whsec_...` است. کلید و شناسهٔ پترن از پنل LimoSMS می‌آیند. این فایل در Git نادیده گرفته می‌شود. هیچ‌کدام را در `EXPO_PUBLIC_*` نگذارید.
5. با Supabase CLI وارد حساب شوید و اجرا کنید:

   ```sh
   npx supabase login
   npx supabase secrets set --env-file supabase/functions/.env --project-ref PROJECT_REF
   npx supabase functions deploy send-sms --project-ref PROJECT_REF --no-verify-jwt
   ```

   JWT برای این hook غیرفعال است چون درخواست از Auth می‌آید؛ امضای Standard Webhooks و زمان امضا قبل از هر ارسال بررسی می‌شوند. endpoint برای فراخوانی مستقیم اپ نیست.
6. hook را فعال کنید. URL و anon key پروژه را در `.env` ریشه مطابق `.env.example` بگذارید و اپ را دوباره اجرا/بیلد کنید.

## بررسی واقعی پس از اتصال

- ثبت‌نام با یک شمارهٔ تحت اختیار خودتان، دریافت کد، تأیید و ورود؛ نام پروفایل باید حفظ شود.
- خروج و ورود دوباره با همان شماره؛ حساب جدید ساخته نشود.
- کد غلط، منقضی و مصرف‌شده پذیرفته نشود؛ محدودیت ارسال و تأیید را بررسی کنید.
- قطع سرویس یا اعتبار ناکافی LimoSMS باید خطا بدهد؛ درخواست بدون امضای معتبر نباید پیامک بفرستد.
- شماره‌های `09…`، `+989…` و ارقام فارسی پشتیبانی می‌شوند.

حساب‌های ایمیلی قبلی خودکار به حساب موبایلی وصل نمی‌شوند. برای حفظ آثارشان، اتصال شماره به همان کاربر باید پس از تأیید مالکیت از مسیر مدیریتی انجام شود.

تست‌های محلی با پاسخ شبیه‌سازی‌شدهٔ سرویس اجرا می‌شوند؛ ارسال واقعی نیازمند تنظیمات بالا و اعتبار پنل است.

منابع: [LimoSMS API](https://api.limosms.com/)، [Supabase Send SMS hook](https://supabase.com/docs/guides/auth/auth-hooks/send-sms-hook)، [ورود موبایلی](https://supabase.com/docs/guides/auth/phone-login).

## سقف هزینه
پیش از استقرار نسخهٔ جدید تابع، مهاجرت 002_profiles_calls_limits.sql را اجرا کنید. سقف پیش‌فرض SMS_DAILY_LIMIT=100 برای کل برنامه در روز UTC، حداکثر ۵ تلاش برای هر شماره و فاصلهٔ ۶۰ ثانیه است. نبود دیتابیس یا تمام‌شدن سهمیه جلوی تماس با لیمو را می‌گیرد.
